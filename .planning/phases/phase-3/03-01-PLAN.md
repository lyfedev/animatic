   surfaces are pure white and all lines are pure black, so the picture reads as flat
   two-tone linework, with clean open white space wherever a surface would otherwise be
   darkened. The illustration sits alone on the page and fills the frame edge to edge as a
   plain drawing in open white margins. The only marks anywhere in the frame are the drawn

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → path construction | reference-art and generated-art filenames become write paths |
| process → Google Gemini Developer API | prompt text out, image bytes in, over an API key held in settings |
| process → S3 `animatic-media-628818` | manifest and art bytes written to a shared bucket |
| script PDF → image prompt | screenplay text flows into text sent to an image model |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `asset_manifest` art write path | medium | mitigate | Build every write path from `Path(name).name` plus a slot_id derived from the resolver's own normalisation, never from a raw external filename; slot_ids are `[a-z0-9_]` by construction |
| T-03-02 | Information Disclosure | `asset_generator` client construction and logging | high | mitigate | Read the key only through `settings.google_api_key`; never log the key, never write it into the manifest, and log prompts rather than client config |
| T-03-03 | Denial of Service | `content_hash` over reference art | low | mitigate | Hash file bytes in chunks with `hashlib.sha256().update()` in a read loop rather than loading whole files into memory (implemented in 03-02) |
| T-03-04 | Tampering | screenplay text → image prompt | low | accept | Script content is the fixed developer-supplied `docs/rocky-1976.pdf`; PROJECT.md forbids user script upload, so no untrusted text reaches the prompt in this milestone |
| T-03-05 | Spoofing | S3 write result | medium | mitigate | `write_manifest` returns and records an honest `s3_ok`/`s3_reason` instead of returning a `local://` URI as if it were a success (the defect logged against `beat_assembler._write_s3`) |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | This phase installs nothing — it uses `google-genai`, `boto3`, `pdfplumber` already in requirements.txt plus stdlib `hashlib`/`difflib`. `pillow` was audited SUS (unknown-downloads data gap) and is deliberately not added: reference art is fixed developer-supplied content, so image-format validation buys nothing here. No package-manager install task exists in this phase, so no legitimacy checkpoint is required |
