the slot list into a manifest that Phase 4 and Phase 5 can consume, including the change

detecting that a slot's art changed.

S3, and an honest S3 writer shared with the beat pipeline.

Create `reference_art.py` with `resolve_reference_art(slots, reference_dir) -> ReferenceScan`,
carrying the matched files per slot and the list of files that matched nothing.

FR-02 asks for reference art "in named slots", and D-01 forbids a hand-curated alias list —
the system makes its best guess and records how it guessed. Two mechanisms, in this order:

1. **Slot directory** — `assets/reference-art/<slot_id>/` holds art for that slot
   explicitly. This is the named-slot interface FR-02 describes and it is unambiguous, so
   it wins outright. match_rule is "slot_directory".
2. **Filename token** — for flat files directly under the reference directory, split the
   file stem on underscores and hyphens and match a slot when every token of the slot_id
   appears among the stem's tokens. `rocky_porkpie.jpg` therefore matches slot `rocky`;
   `boxing_poses.jpeg` matches nothing. Use token matching, not bare substring matching, so
   a short slot_id such as `fan` cannot swallow an unrelated filename. match_rule is
   "filename_token".

Record on each matched slot: `source` = "reference", `source_files` (sorted, repository-
relative), `match_rule`, and a `source_reason` naming the mechanism and the files, e.g. that
three files matched slot id `rocky` on filename tokens and that reference art takes
priority over generation. A slot that matched nothing keeps `source` unset here; Task 2
fills it as "generated".

Files that matched no slot go into `ReferenceScan.unmatched` with a reason line; the
manifest surfaces them as `unmatched_reference_files` so a mis-named file is visible rather
than silently ignored (NFR-04). `boxing_poses.jpeg` is the live example — it is a real
supplied file that no slot_id claims.

The active art for a reference slot is its first file in sorted order; the remaining files
stay in `source_files` for Phase 4, which can condition on several reference images at once.
Do not generate art for a reference slot — reference beats generation, which is exactly
ROADMAP criterion 3.

Add `content_hash_file(path)` hashing in chunks with `hashlib.sha256().update()` rather than
reading whole files into memory (T-03-03). Build every path from `Path(name).name` plus a
resolver-produced slot_id; never join a raw filename from the directory scan into a write
path (T-03-01).

Extend `tests/test_asset_manifest.py` with `test_reference_art_takes_priority`,
`test_unmatched_reference_file_is_recorded`, `test_slot_directory_beats_filename_token`
and `test_content_hash_changes_on_file_replace`, using tmp_path for the synthetic cases and
the real `assets/reference-art/` for the supplied-files case.

**Manifest shape.** `build_manifest` follows `beat_assembler._build_beat_list` exactly —
`generated_at`, `script`, then top-level counts, then the slot list. Top level carries:
`total_slots` (16), `character_slots` (9), `location_slots` (7), `art_slots` (distinct
art_slot_id count), `reference_backed`, `generated`, `beats_source` and the beat list's own

`unmatched_reference_files`, `stale_beat_ids`, `s3_ok` and `s3_reason`. Each slot entry
carries the full `Slot` field set from 03-01. ROADMAP criterion 5 is satisfied per entry by
slot_id/display_name plus priority_rank plus source plus the reason fields, and NFR-04 by
`merge_reason`, `priority_reason`, `source_reason` and `prompt` all being non-empty for the
cases they apply to — following Phase 2's precedent of a value plus the rule that produced
it, the way `duration_source` names which rule set a beat's duration.

**Change detection (ROADMAP criterion 4).** Read the previous `output/assets/manifest.json`
if present. For each slot compare the new `content_hash` against the previous one for the
same slot_id: differing, newly-appearing or source-flipped art sets `art_changed` True.
`stale_beat_ids` is the sorted union of `beat_ids` across all changed slots, and its reason
line names which slots changed and why. That list is precisely the set of panels Phase 4
must redraw — Phase 3's job is to name them faithfully; Phase 4 owns the redraw itself.
Content hashing was chosen over mtime because it is re-runnable and does not depend on
filesystem timestamps.

**Honest S3 writes.** Create `s3_writer.py` with `put_bytes(key, body, content_type) -> S3Result`
carrying `uri`, `ok` and `error`, wrapping the session/profile handling currently inlined in
`beat_assembler._write_s3` (named profile locally, task role in ECS). On `ClientError` it
logs at ERROR and returns `ok=False` with the message — it never fabricates a success.
`asset_manifest.write_manifest` writes locally first, then puts the manifest and each art
file through `put_bytes`, and records `s3_ok`/`s3_reason` in the manifest body itself so the
artifact states whether it reached the bucket. `scripts/build_assets.py` prints a loud
warning when `s3_ok` is False while still exiting 0, so a developer without AWS credentials
can still build locally.

Fold the same honesty into `beat_assembler._write_s3` by routing it through `put_bytes`:
keep its existing return contract so Phase 2's API and CLI are untouched, but log the
failure at ERROR rather than WARNING and return the `local://` marker only from the single
place that now knows the write genuinely failed. This is the cheap half of the deferred
`beat_assembler` fix — the deduplication and the honest result object. Changing
`POST /beats/parse` to surface the failure to its caller is not folded in: it would change
a verified Phase 2 response contract and its test for no Phase 3 criterion, so it stays in
the backlog. Run the Phase 2 suite to confirm nothing regressed.

| T-03-03 | Denial of Service | `content_hash_file` over reference art | low | mitigate | Chunked `hashlib.sha256().update()` read loop rather than whole-file reads (Task 1) |
